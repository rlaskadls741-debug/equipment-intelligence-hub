01 / PURPOSE

만든 목적

PC 제어 프로그램의 실행 경로를 PLC 시퀀스처럼 눈으로 따라가며 전체 구조를 익힌 뒤, 필요한 코드의 디테일을 이해하도록 돕는 것이 이 지도의 목적입니다.

기존 분석 TOOL에는 전체 동작 흐름, 함수 호출 관계, 선언·구현 위치와 원문·해설이 이미 있었습니다. 하지만 관계가 텍스트 중심으로 제시되어, 사용자가 여러 내용을 읽고 머릿속에서 연결해야 했습니다. 파일과 함수가 많을수록 학습을 시작하기 어려웠습니다.

PC 프로그램은 파일의 첫 줄부터 끝 줄까지 한 번에 내려가는 구조가 아닙니다. 함수 안의 처리 중 다른 함수를 호출하고 돌아오며, 버튼·메시지·타이머·스레드 등 서로 다른 계기로 실행이 시작됩니다. 따라서 파일 순서와 실행 순서를 구분해서 볼 화면이 필요했습니다.

학습의 순서
전체 실행 지도 → 시작점 선택 → 조건·호출·반복 경로 추적 → 함수 내부 탐색 → 원문·해설·선언 확인

기존 TOOL과 같은 분석 데이터를 사용하는 별도 HTML로 제작했습니다. 기존 분석 화면과 원본 C++ 자료를 보존하면서 다른 방식으로 학습할 수 있도록 했습니다.

02 / DESIGN DIRECTION

만든 방향성

큰 그림에서 세부 코드로

처음에는 주요 실행 시작점과 작업 간 관계를 보고, 관심 있는 함수 안으로 들어가도록 구성합니다.

실제 실행 관계를 그림으로

처리, 조건 분기, 함수 호출, 반복, 반환을 구분합니다. 서로 다른 시작점과 스레드의 실행을 하나의 연속 작업으로 오해하지 않도록 합니다.

들어간 곳과 돌아올 곳 유지

함수를 탐색하는 동안 호출 경로를 남깁니다. 호출 위치로 복귀한 뒤 다음 처리를 이어서 확인할 수 있도록 합니다.

역할을 먼저, 코드는 그다음

박스에서 무엇을 위한 단계인지 읽고, 선택하면 실제 처리 목록과 설명·원문 행을 확인하도록 합니다.

일반 호출과 별도 작업 구분

일반 호출은 대상 함수 처리 후 호출 위치로 돌아옵니다. 스레드 생성은 별도 작업을 시작하도록 요청한 뒤 현재 함수가 계속 진행하는 관계로 설명합니다.

읽기 쉬운 연결과 배치

일반 흐름은 위에서 아래로, 조건 내부는 예·아니오 경로로 구분합니다. 긴 반환·반복선은 목적지 표시와 이동 버튼으로 따라가도록 합니다.

선언·호출·구현을 다루는 기준

구분지도에서의 역할
선언함수의 이름·입력·반환 형식과 헤더 위치를 확인하는 자료입니다. 실행 단계로 배치하지 않습니다.
호출다른 함수의 처리가 시작되는 위치입니다. 여기에서 대상 함수로 들어가고 호출 위치로 복귀합니다.
구현조건 검사, 상태 변경, 장치 명령, 하위 호출과 반환을 실제로 수행하는 함수 본문입니다.
03 / CHANGE HISTORY

수정 및 개선사항

기록일: 2026년 10월 28일 · 같은 날 진행한 제작·수정을 단계별로 정리했습니다. 기존 분석 TOOL 전체의 개발 이력은 별도 기록입니다.

1차 제작

별도 실행 경로 지도 추가

출발점: 호출 관계가 텍스트 중심이라 전체 실행 흐름을 눈으로 따라가기 어려웠습니다.

  • 주요 시작점과 초기화·입력 감시·자동 작업의 관계를 전체 지도에 배치했습니다.
  • 214개 함수의 조건·반복·호출·반환 구조를 원문에서 추출했습니다.
  • 조건 경로 선택, 함수 안으로 진입, 호출 위치 복귀, 호출 경로 표시를 추가했습니다.
  • 원문·해설·현재 함수와 호출 대상의 선언·구현 위치를 연결했습니다.
  • 스레드 시작, 동기 메시지 전달과 MFC 초기화 콜백을 일반 호출과 구분했습니다.

기준 커밋: bcc8687

2차 개선

추상적인 문장 수 표시를 실제 동작 목록으로 변경

사용자 피드백: ‘2개 문장 · 변수 초기화·상태 변경·외부 호출 등’이라는 제목만으로는 실제로 무엇을 하는지 알기 어려웠습니다.

묶음 설명만 제시각 동작의 개별 설명과 원문 행을 유지하고 선택 창에서 확인

3차 개선

박스 배치·연결선·실행 순서·단계 역할 개선

사용자 피드백수정·개선 내용
박스가 겹쳐 앞 박스에 가림분기·반복문이 차지하는 실제 폭과 높이를 계산해 하위 박스를 배치하도록 변경했습니다. 묶음 보기와 한 문장 보기 모두 겹침을 검사합니다.
연결선이 복잡함일반 진행은 짧은 연결선으로 표시하고, 화면 전체를 가로지르던 반환·반복선은 목적지 표시와 이동 버튼으로 바꿨습니다. 조건의 예·아니오 글자 위치도 분리했습니다.
실행 순서가 애매함기본 흐름, 특정 조건의 예·아니오 경로, 반복문 본문을 표시했습니다. 반복 본문의 끝에 ‘반복 조건 다시 확인’을 추가하고, do/while은 본문을 먼저 실행한 뒤 조건을 검사하도록 배치했습니다.
‘순서대로 처리’가 어떤 역할인지 불명확함‘ECAT 자동 작업 시작 준비’, ‘START·STOP·RESET 입력 감시 준비’처럼 역할 제목과 이유를 붙이고, 그 아래에 실제 동작을 표시했습니다.

호출 박스의 설명창에는 대상 함수 처리 후 복귀하는 순서와, 별도 스레드 생성 요청 후 현재 함수가 계속 진행하는 관계를 구분해 설명했습니다.

기준 커밋: 565acf2

4차 개선

분기 방향 통일·한 화면 전체 조감도 추가

사용자 피드백: 조건마다 예·아니오 방향이 바뀌고, 전체 흐름을 한눈에 볼 화면이 부족했습니다.

  • 함수 내부 if·while·for·do/while 조건의 출구를 예는 아래, 아니오는 오른쪽으로 통일했습니다. do/while도 조건 아래에 반복 연결점을 두고 본문으로 돌아가도록 표시합니다.
  • 프로그램 시작, 초기화, 입력 감시, 버튼·수동 조작, 자동 작업 두 개, STOP·RESET·종료를 연결한 프로그램 전체 조감도를 첫 화면으로 추가했습니다.
  • 조감도는 사이드바를 접고 화면 크기에 맞춰 전체를 표시합니다. 확대해서 이동할 수 있으며, 박스를 누르면 해당 함수 또는 관련 함수 선택 창이 열립니다.
  • 기존 세 묶음의 설명 화면은 ‘학습 경로 안내’로 분리했습니다.
  • 모든 함수의 두 보기 방식에서 분기 출구 방향·박스 겹침·선 관통을 다시 검사하고, 조감도의 함수 연결과 주요 단계·배치도 검사했습니다.
5차 개선

종료 대기·이동 완료 반복문의 설명 정정

조건을 기계적으로 풀어 쓴 문장 때문에 반복의 목적과 종료 조건이 불명확했습니다. 감시·입력·자동 작업의 종료 대기는 실행 표시가 켜져 있는지 묻는 제목과, 반복 중 하는 일·대기를 끝내는 조건으로 나눠 설명했습니다. 이동 완료 대기도 두 축의 상태를 다시 읽고 종료하는 조건을 명시했습니다. 제목과 본문이 같을 때 같은 설명을 두 번 표시하지 않도록 변경했습니다. 원본 C++는 변경하지 않았습니다.

6차 개선

AUTO 탭 Run 명칭·입력 경로 구분 정정

실제 화면의 ‘AUTO 탭 Run’ 버튼을 ‘화면 START 버튼’으로 표기해 외부 START 스위치와 혼동될 수 있었습니다. 조감도·탐색 메뉴·학습 안내·실행 코드 해설의 화면 버튼 이름을 실제 명칭에 맞췄습니다. Run 버튼은 OnButtonAutoRun으로 직접 들어가고, 외부 START 스위치는 OnAutoRun → OnAutoRunUpdate를 거쳐 같은 함수로 합류하는 구조를 명시했습니다. 함수 진입 설명에도 두 입력의 합류 관계를 추가했습니다. 원본 함수명과 C++ 코드는 변경하지 않았습니다.

04 / VERIFICATION & SCOPE

확인한 범위와 사용 기준

자료 범위: 원본 C++ 79개 파일, 함수 색인 214개. 동작 묶음 보기 기준으로 3,489개 노드와 3,930개 의미상 연결을 검사했습니다. 반환·반복 등 일부 연결은 긴 선 대신 목적지 표시로 표현합니다.

  • 자동 검사: 연결 대상, 원문 행 범위, 조건 분기, 반복 복귀, 함수 반환, 스레드 구분, 묶음 내부 설명 보존을 확인했습니다.
  • 배치 검사: 214개 함수의 두 보기 방식 모두에서 박스 겹침과 연결선의 무관한 박스 관통 여부를 검사했습니다.
  • 순서 검사: do/while의 본문 우선 실행과 조건 행, 예·아니오 표시 위치를 확인했습니다.
  • 브라우저 확인: 주요 실행 경로에서 조건 선택, 함수 탐색·복귀, 선언·원문 보기, 역할 설명과 개선된 배치를 확인했습니다. 모든 함수의 모든 경로를 수동 확인한 것은 아닙니다.
학습용 정적 지도입니다.
실제 프로그램이나 설비를 실행하지 않으며 조건 값은 사용자가 선택합니다. 스레드 스케줄링과 실제 호출 시각을 계측하지 않습니다. switch 내부는 원문 묶음으로 표시하며, SDK·MFC 내부 구현과 전처리 조건·매크로 확장은 이 지도에서 실행·계산하지 않습니다.

배치·참조 검사의 통과는 실제 설비 동작, 런타임 실행 순서 또는 컴파일러 수준의 제어 흐름 정확성을 보증하는 의미는 아닙니다. 세부 판단은 연결된 원문과 기존 분석 TOOL의 근거를 함께 확인합니다.
