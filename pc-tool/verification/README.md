# PC Tool 검증 기록

`report.json`은 2026-10-21 검사 대상과 실제 검사 결과, 항목별 결과, 수정 사항, 미완료 범위를 기록한다.

## 확인 단계

1. 원본 export 바이트 SHA-256과 provenance를 비교한다.
2. 원본을 FILE 블록으로 독립 분리한다. 업로드 PART 9개와 82개 블록의 내용을 대조한다.
3. HTML의 79개 C++ 파일을 원본과 비교한다. CRLF→LF 및 파일 끝 빈 줄 정리가 기준이다. 여섯 파일에서 제거된 끝 빈 행 수를 개별 기록한다. 코드 내용의 바이트 동일성 검사와 원본 export의 바이트 SHA 검사는 별개다.
4. 중첩 원문 참조, 함수·호출 토큰/소속, 스레드 등록·메시지 맵, 사전 예제의 실제 코드, 지역 변수·매개변수 범위, 도식 링크·간선의 양끝과 대응을 모두 검사한다.
5. `control-checks.json`의 39개 제어 설명에 대해 실제 코드의 조건·순서·활성/주석 여부를 확인한다. IO·축 번호 27개와 DWORD 패킹 4가지를 검사한다. 업로드 motion.mot의 4축 원시 값을 대조한다.
6. 도식 42개를 검토한 기록과 제품 PDF·공식 문서·문법 설명의 확인 범위를 남긴다.
7. 브라우저에서 화면/이력 링크, 검색, 원문 이동, 사전, 직접 원문 링크를 확인한다. 그 결과는 별도 UI 재현 기록이며 C++ 실행 검증이 아니다.

## 통과가 뜻하지 않는 것

- 자연어 해설 14,622행과 프로젝트 사전 목적·용도 문장의 전 문장 독립 의미 검토 완료
- 컴파일러 AST·이름 해석·오버로드·매크로 전개·스레드 순서 검증
- SDK 47개 항목의 모든 계약과 적용 버전 검증
- 현재 장비의 INI/MOT/PDO/배선/기구/실행 결과 검증

위 항목들은 미완료 기록이다. 검사 합계나 0건 실패를 '모든 설명이 사실'이라는 인증으로 사용하지 않는다. 같은 참조를 서로 다른 검사에서 다시 확인하므로 검사 합계를 고유 기능 수로 해석하지 않는다.

## 재현

프로젝트 루트에서 원래 업로드 파일의 경로를 지정한다.

```bash
node pc-tool/verification/export-data.cjs /tmp/control-trace.json
python pc-tool/verification/audit.py \
  --data /tmp/control-trace.json \
  --original /path/DemoKit_FULL_EXPORT.txt \
  --parts-dir /path/parts \
  --mot /path/motion.mot \
  --out /tmp/audit-results.json
node --test pc-tool/tests/*.test.cjs
```

브라우저 로더와 같은 설명 수정 모듈을 적용한 뒤 검사한다. 원본 C++ 데이터는 수정하지 않는다. `build-report.py`는 검사 결과에 검토 메모와 미완료 항목을 합쳐 공개 기록을 만든다. 입력 자료나 수정 모듈이 바뀌면 새 검사 이력을 작성해야 한다.
