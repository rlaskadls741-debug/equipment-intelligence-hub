# 실행 경로 따라가기

별도 실행 화면: [execution-map.html](../execution-map.html)

제작 목적·설계 방향·수정 및 개선 이력: [execution-map-history.html](../execution-map-history.html)

전체 실행 지도에서 시작점 선택 → 조건 경로 선택 → 호출 함수 진입 → 호출 위치로 복귀. 오른쪽 창에서 원문·해설·현재 함수와 호출 대상의 선언을 확인한다. 스레드 생성과 동기 메시지 전달, MFC 콜백을 직접 호출과 구분한다.

기존 source-part1.txt / source-part2.txt의 control-trace 데이터를 읽어 214개 함수의 구조를 생성한다. 기존 TOOL과 원본 C++ 데이터는 수정하지 않는다. 생성된 HTML은 외부 라이브러리 없이 단독 실행한다.

갱신:
```sh
python pc-tool/execution-map/build.py
node pc-tool/tests/execution-map.test.cjs
```

정적 학습용이다. 조건 값이나 스레드 스케줄링을 실행·계산하지 않는다. if/else, while/for/do, return/break/continue의 구조를 표시하며 switch 본문은 원문 묶음으로 표시한다. SDK 내부 구현과 MFC 내부 실행 코드는 포함되지 않는다. 전처리 조건과 매크로 확장은 계산하지 않으며, 컴파일러 수준의 제어 흐름 분석을 대체하지 않는다.

검증: 214개 함수, 3,489개 노드와 3,930개 연결의 참조·원문 범위·분기·반복 복귀·반환·스레드 분리를 자동 확인. 브라우저에서 조건 경로 선택, 함수 진입·호출 위치 복귀, 선언 보기와 관련 흐름도를 확인한다.

## 2026-10-28 배치·실행 순서 개선

- 분기·반복문이 차지하는 실제 높이와 폭을 계산해 하위 박스를 배치한다. 묶음/한 문장 보기 모두 214개 함수의 박스 겹침과 선의 무관한 박스 관통을 검사한다.
- 일반 진행은 위에서 아래로, 조건 본문은 예/아니오 경로 표시로 구분한다.
- 반환은 현재 함수 종료, 반복은 조건으로 이동하는 목적지 표시로 처리한다. 화면 전체를 가로지르는 반환·반복 연결선은 그리지 않는다. 의미상 연결은 유지되어 이동 버튼으로 따라갈 수 있다.
- 반복 본문의 끝에 ‘반복 조건 다시 확인’을 표시하고 do/while은 본문부터 시작한다.
- 묶음에는 역할 제목과 이유, 실제 동작 목록을 함께 표시한다. 일반 호출의 복귀와 별도 스레드 시작 후 진행을 구분해 설명한다.

## 분기 방향·전체 조감도

- 함수 내부 모든 if/while/for/do 조건 출구: 예 ↓ / 아니오 →. do/while의 예 경로는 아래 연결점을 통해 위쪽 본문으로 이동한다.
- 첫 화면은 시작·초기화·감시·입력·자동 작업·수동 조작·정지·종료를 요약한 전체 조감도다. 화면 크기에 맞춰 전체를 표시하고, 확대와 함수 탐색을 제공한다.
- 기존 설명 화면은 ‘학습 경로 안내’로 분리했다.
- 자동 검사에 두 보기 방식의 분기 출구 방향, 조감도 단계·함수 참조·영역·선의 박스 관통 검사를 추가했다.

## 현재 설비 기준 · Run과 기존 IO

- 사용자가 확인한 운전 시작 경로: AUTO 탭 Run → MFC 버튼 이벤트 → OnButtonAutoRun → StartAutoRun.
- IO는 이미 구성된 설비 기준이다. 프로그램이 기존 DO로 명령하고, 기존 DI를 읽어 조건을 판단한다. 사용자가 DI 값을 별도로 입력하거나 Run 전에 IO를 새로 설정하는 절차가 아니다.
- Run 클릭이 m_Dpr.m_bInput[0]을 직접 변경하는 구조는 아니다.
- DI0/1/2를 START/STOP/RESET 조건으로 보는 코드는 별도 참고 창에서 보존한다. 실제 DI0 신호원은 미확인이다. 물리 START 버튼의 존재 또는 해당 코드의 미사용 여부를 단정하지 않는다.
- 조감도에서는 Run 경로와 기존 DO 명령·장치·DI 상태 관계를 보여주고, 코드상 DI 조건 경로는 참고로 분리했다. IO 선은 명령·상태 관계 요약이며 모든 IO 동작이 완료 대기를 한다는 뜻은 아니다.

## 하드웨어·컨베이어 화면

- 모션 4축 / 일반 DO 밸브 / 인버터 1·2 경로를 분리한다. 화면 상단 버튼으로 열며 각 박스에서 실제 함수를 탐색한다.
- 인버터 1: ECAT 자동 작업 483행 true → 모듈 2 DWORD 0xFE01000F. 루프 종료 후 540행 false → 0.
- 인버터 2: PM2Q 자동 작업 566행 true → 모듈 3 DWORD 0x01FF000F. 루프 종료 후 608행 false → 0.
- 자동 인버터 코드는 AxdoWriteOutportDword를 직접 호출한다. 일반 NX DO 비트 제어와 구분하며 출력 명령과 실제 동작 완료 판정을 구분한다.

### 입출력 방향 표기

- 출력: PC → DO 모듈 → 장치. 입력: 센서 → DI 모듈 입력 단자 → PC의 상태 읽기. DI에 명령을 쓰지 않는다.
- 조감도의 IO 선은 신호 관계이며 함수 호출 순서가 아니다. 모션 축 이동을 일반 DO 명령으로 해석하지 않는다.
